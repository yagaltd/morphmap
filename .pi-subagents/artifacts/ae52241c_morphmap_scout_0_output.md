Key findings:

- **Two protocols**: `Minions` (plural, code-gen pipeline, ~1000 lines) vs `Minion` (singular, chat-based, ~790 lines). Both are supervisor-worker but decompose differently.
- **Planner (cloud) writes code**, executor (local) runs it — `prepare_jobs()` and `transform_outputs()` are generated by the cloud model and `exec()`'d. This is the central insight.
- **Contract is `JobManifest`/`JobOutput`** Pydantic models — structured, validated by `model_validate_json()`, not free text.
- **Error handling is thin**: truncated outputs get None answers, unknown `done_reason` crashes, no worker retry loops, no timeouts on main path.
- **Model selection is mostly static** — you pick local/cloud at construction time. `AutoMinion` adds dynamic selection among Together-hosted models but that's a special case.
- **State passes via `last_jobs`, `scratchpad`, `feedback`** between rounds in plural protocol. Singular protocol just appends to message history.
